Quick start

Three steps. This is the pattern we tested and know works.

Add a container where the editor should appear, and give it a size.
Load the script with defer.
Create the editor once the page has loaded.
index.html — a complete working page
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My lesson</title>

  <!-- 1. Load the editor. "defer" = don't block the page while it downloads -->
  <script src="https://phinex-org.github.io/X-Code/XCode.js" defer></script>

  <style>
    #my-editor { width: 100%; height: 500px; border-radius: 8px; overflow: hidden; }
    #my-editor .xce-viewer { height: 180px !important; }   /* console height */
  </style>

  <script>
    /* 3. Create the editor after the page (and the deferred script) are ready */
    document.addEventListener('DOMContentLoaded', () => {
      const editor = new XCodeEditor({
        container: '#my-editor',
        language:  'javascript',    // pick ONE language
        viewer:    'console',       // 'console' | 'page' | 'none'
        ai:        true,            // ghost-text suggestions, Tab to accept
        initialCode: `console.log("Hello from X Code 🚀");

for (let i = 1; i <= 5; i++) {
  console.log(\`Count: \${i}\`);
}`
      });
    });
  </script>
</head>
<body>
  <!-- 2. The container -->
  <div id="my-editor"></div>
</body>
</html>
One thing to avoid: an early test page used language: 'html' || 'javascript'. In JavaScript that expression always evaluates to 'html' (the right-hand side is never reached), so a JavaScript lesson would be highlighted as HTML. Use a single plain string, as above.
Why defer and DOMContentLoaded? Deferred scripts run after the HTML is parsed but before DOMContentLoaded fires. Creating the editor inside that event guarantees both your container and the XCodeEditor class exist. Skip either one and you'll see “XCodeEditor is not defined” or “container not found”.

Building a course site

For a lesson page, put an editor beside the explanation and let the learner run it. HTML and CSS lessons work best with viewer: 'page' — the result renders live under the editor as they type. Each editor is created from its own container, so a page can hold as many as it needs.

Live demo — an HTML lesson with a live previewChange the colour and watch it update
An HTML lesson with a live preview
const lesson = new XCodeEditor({
  container: '#lesson-editor',
  language:  'html',
  viewer:    'page',          // render the HTML live instead of showing a console
  viewerHeight: '220px',
  ai: false,                  // turn suggestions off for beginner exercises
  initialCode: `<h1 style="color: tomato">Change my colour!</h1>
<p>Edit the code on the left side.</p>`
});

Checking a learner's answer

Use onChange to react as they type, or onRun when they press Run. Read the current code with getValue().

A simple “did they do it?” check
const exercise = new XCodeEditor({
  container: '#exercise',
  language: 'javascript',
  initialCode: '// Task: log the word "done"\n',
  onRun(code) {
    const passed = /console\.log\(\s*['"`]done['"`]\s*\)/.test(code);
    document.getElementById('result').textContent =
      passed ? '✅ Correct — nice work!' : '❌ Not yet — log the word "done".';
  }
});
Heads-up: checks like this run in the learner's browser, so they're great for friendly feedback but shouldn't be used for anything that needs to be tamper-proof (grades, certificates).

Styling

Size the editor with ordinary CSS on your container, and recolour it with CSS variables:

CSS
#my-editor {
  width: 100%;
  height: 500px;
  --xce-accent:    #39ff14;   /* highlights and buttons */
  --xce-bg:        #1e1e1e;   /* editor background */
  --xce-font-size: 13px;
}
#my-editor .xce-viewer { height: 200px; }   /* output panel */

Questions

Do I need to install anything?

No. It's a single JavaScript file loaded with a normal <script> tag — no build step, no framework required.

Can I put several editors on one page?

Yes — give each its own container element and create one XCodeEditor per container, like the two live demos on this page.

Does this need the desktop app?

No. The embeddable editor is separate from the X Code desktop app. The desktop app is the full editor you install; this is the small version for web pages.

What happens if the AI service is unavailable?

Suggestions simply don't appear — typing, highlighting and running code keep working. Set ai: false if you'd rather never show suggestions.
